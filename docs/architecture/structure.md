# 구조 가이드

## 코드 배치

- `apps/web`: 화면, 사용자 상호작용, API 호출
- `apps/api`: 인증·권한 검증, 비즈니스 규칙, 데이터 접근
- `packages/shared`: 웹과 API가 공유하는 계약과 검증 규칙. 서버 비밀값과 데이터베이스 접속 코드는 두지 않습니다.
- `database`: 스키마 변경과 개발용 데이터
- `tests`: 앱 또는 기능을 가로지르는 검증. 단위 테스트는 구현 코드 가까이에 배치합니다.

## 기능 경계

| 디렉토리 | 책임 |
| --- | --- |
| auth | 인증과 세션 |
| users | 회원 프로필 |
| neighborhoods | 활동 동네와 지역 탐색 |
| clothes | 의류 정보와 대여 가능 조건 |
| rentals | 대여 요청, 예약 중복 방지, 상태 전이 |
| chat | 대여 당사자 간 대화 |
| reviews | 대여 완료 후 후기 |
| notifications | 사용자 알림 |

기능 내부의 파일 구성은 선정한 프레임워크에 맞춰 추가합니다. 현재 구조는 프레임워크를 확정하지 않습니다.

## 설계 시 고려 사항

- 권한 검증과 대여 상태 변경은 서버가 담당합니다.
- 예약 확정 시 같은 의류의 기간 중복을 데이터베이스 트랜잭션 등으로 방지합니다.
- 정확한 주소와 연락처의 공개 범위는 최소화하고 정책을 명시합니다.
- 의류 사진은 외부 파일 저장소를 사용하고 비밀값과 업로드 파일은 Git에 저장하지 않습니다.
